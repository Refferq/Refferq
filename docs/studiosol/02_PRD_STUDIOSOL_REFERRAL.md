# PRD — StudioSol Referral Program (на базе Refferq)

## 1. Цель продукта

Запустить реферальную программу StudioSol, которая:

- привлекает новых платящих клиентов через партнёров;
- прозрачно считает вознаграждения;
- автоматизирует выплаты;
- даёт управляемую аналитику unit-экономики.

## 2. Бизнес-цели (на 6 месяцев)

- Доля new MRR из рефералов: `>= 20%`.
- CAC из referral-канала ниже paid-каналов минимум на `30%`.
- Время от конверсии до подтверждённой комиссии: `< 24h` (с учётом hold policy).
- Доля спорных/ошибочных начислений: `< 1%`.

## 3. Персоны

1. Партнёр (Affiliate)
- Получает реф-ссылку/код.
- Отслеживает клики, регистрации, оплаты, начисления, выплаты.

2. Партнёр-менеджер / Admin StudioSol
- Управляет партнёрами, правилами комиссий, исключениями, выплатами.

3. Finance/Ops
- Закрывает расчёты, проверяет акты/инвойсы, ведёт отчётность.

## 4. Scope MVP

### In-Scope

- Регистрация и активация партнёров.
- Реферальная атрибуция (link + code + cookie/window).
- Трекинг conversion (платёжные события).
- Начисление комиссии по правилам.
- Hold period + mature/approve.
- Массовая генерация payouts.
- Базовые email/уведомления.
- Дашборды для admin и affiliate.

### Out-of-Scope (для MVP)

- Multi-tenant для нескольких брендов.
- Сложные многоуровневые агентские сети.
- Dynamic ML anti-fraud.
- Полная self-serve billing-интеграция для всех PSP одновременно.

## 5. Функциональные требования

### FR-01 Партнёрский аккаунт
- Регистрация партнёра с KYC-light полями.
- Статусы: `PENDING -> ACTIVE -> SUSPENDED`.

### FR-02 Атрибуция
- Генерация персональной ссылки и кода.
- Сохранение attribution key/cookie с TTL.
- Last-touch/first-touch политика задаётся в настройках.

### FR-03 Tracking API
- Приём событий `referral_click`, `conversion_created`, `conversion_paid`, `refund`.
- Валидация подписи и idempotency-key.

### FR-04 Комиссии
- Процентная/фиксированная модель.
- Разные правила по партнёрским группам.
- Hold period (например, 14/30 дней).

### FR-05 Выплаты
- Генерация payout batch по расписанию.
- Статусы выплаты: `PENDING/PROCESSING/COMPLETED/FAILED`.
- Экспорт в CSV + журнал проводок.

### FR-06 Админ-панель
- Управление партнёрами, рефералами, комиссиями, выплатами.
- Ручная корректировка с обязательным audit trail.

### FR-07 Партнёрский кабинет
- Баланс (pending/approved/paid).
- История конверсий и выплат.
- Маркетинговые материалы.

### FR-08 Уведомления
- Email для ключевых событий: регистрация, одобрение, начисление, выплата.

## 6. Нефункциональные требования

- Безопасность:
  - секреты только через env/secret manager;
  - HMAC/подписи webhook;
  - rate limiting на публичных endpoint.
- Производительность:
  - p95 API latency < 300ms для read операций.
- Надёжность:
  - idempotent event processing;
  - retry policy + DLQ для внешних вызовов.
- Наблюдаемость:
  - централизованные логи, error tracking, бизнес-метрики.

## 7. KPI продукта

- Activation rate партнёров.
- Click -> Signup conversion.
- Signup -> Paid conversion.
- Общий payout accuracy.
- Refund-adjusted ROI по referral-каналу.

## 8. Ограничения и допущения

- StudioSol предоставляет достоверный источник событий оплаты.
- Юридическая модель выплат и налогообложения подтверждена.
- Команда запускает MVP в одном основном регионе и валюте, затем масштабирует.

## 9. Критерии приемки MVP

- От клика до выплаты путь закрыт end-to-end.
- Все финансовые действия аудируются.
- Есть мониторинг ошибок и алерты по критическим сценариям.
- Есть регламент инцидентов и ручного reprocessing событий.
